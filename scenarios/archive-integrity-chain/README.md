# archive-integrity-chain

The hash chain 0.9.25 lays over the daemon's per-window NDJSON archive, read
back through `disclose`.

## Why it exists

Before 0.9.25 the integrity story stopped at the published document. The
`content_hash` and the cosign signature proved a report had not moved since it
was generated — but the archived windows it was aggregated *from* carried
nothing at all. Editing one window before running `disclose` produced a
perfectly coherent report with a valid hash, and no scenario here could tell.

Each archive line now records `{ts, report, prev, seq, hash}`, where the hash
covers the first four. `disclose` walks the chain while it aggregates and
publishes the verdict under `integrity.trace_integrity_chain`.

## What it asserts

| id | assertion |
|----|-----------|
| A | an intact archive: `breaks = 0`, `windows_verified` equals the number of windows |
| B | one window edited in place: `breaks = 1`, and the report is still produced |
| C | an archive written before chaining existed: `windows_unchained = N`, `breaks = 0` |
| D | the `hash` field removed *after* the chain started: counted as a break |
| E | `SIGKILL` mid-write then a restart: `breaks = 0` |
| F | a deterministically torn tail then a restart: the torn line is a lost window, `breaks = 0` |

D is the assertion that closes B's obvious workaround. Without the anti-strip
rule, deleting the `hash` field would be a way to rewrite a window and still
publish zero breaks — so a line with no hash is benign only *before* the file's
chain has started.

E and F are the same guarantee from two angles. E is the operational shape:
`kill -9` a daemon that is writing, restart it, and check the restart does not
read as tampering — it cannot promise it will tear a line. F cuts the last line
in half by hand, which is the case the product fixed at the very end of the
branch and had only ever run under unit tests.

## What it found (2026-08-02, pre-release 0.9.25)

6/6. The five behaviours the handoff describes all hold, including the
last-minute truncation fix: after tearing the tail and restarting, 29 windows
verified out of 30 physical lines, with `breaks = 0`.

## Known limits, by design upstream

- **A clean truncation of the file's tail is invisible to the chain alone.**
  What remains is a shorter but self-consistent chain, and `seq` cannot close
  that either since the reader counts the lines it was given. Detecting it needs
  an anchor kept outside the file, which `integrity.cross_period_log` stays
  reserved for. F tears a line rather than removing whole lines, so it measures
  the case the chain *can* see.
- **A version rollback produces breaks without tampering.** Running 0.9.24
  against an archive whose lines are chained appends unchained windows after
  chained ones, which the anti-strip rule of D counts as a break. Rotate the
  archive before a downgrade. This scenario does not exercise that path: it is
  an accepted upstream trade-off, not a defect.
- **Tamper-evidence, not proof of a sincere source.** Whoever controls the
  daemon and its files can regenerate a consistent chain. Both the product docs
  and this scenario's assertions stay inside what the chain actually claims.

## How it works

The archive is generated by a **real daemon** on every run rather than committed
as a fixture, so the chain always matches the binary under test. Traffic comes
over the daemon's JSON socket: eight sibling `SELECT`s per trace clears
`n_plus_one_min_occurrences`, so each window carries a finding and an avoidable
share worth archiving. `[green] enabled = true` is mandatory — the daemon
refuses the archive pairing otherwise, since windows with no energy make
`disclose` meaningless.

Two things constrain the plumbing:

- `TMP_DIR` is `/tmp/<scenario>` and must stay short. The JSON socket lives
  there, and a Unix socket path is capped near 104 bytes; a longer working
  directory fails to bind with `path must be shorter than SUN_LEN`.
- The window cadence is `trace_ttl_ms`, not a timer: the daemon archives one
  window per eviction cycle that carried traffic. 1 s keeps the run short.

The period is a `custom` window ±120 days around today, so a run started minutes
before a month or quarter boundary never lands on an empty period.

## Run

```sh
cargo build --release          # in the perf-sentinel checkout
make verify-archive-integrity-chain
```

Self-contained: no cluster, no Docker. Needs the local release binary and
python3. Around 90 seconds. Report at
`/tmp/scenario-archive-integrity-chain-report.md`.
